# 2026-10-02 v0.29.0 新規事業タブと肉の販売

## 経緯
v0.28.0に対するフィードバック:

- 市場タブを削除し、新規事業タブに変更
- 新規事業タブではある一定額(高額)を消費することで、拠点に新たな新規事業を行うスペースを拡張する
- 新規事業の案として、肉の販売(狩猟エリア、肉販売カウンタ)の追加、魚の販売(釣り場エリア、魚販売
  カウンタ)の追加、農業エリア(小麦栽培エリア、小麦販売エリア)の追加等、数多く追加予定(追加項目は
  提案すること)

規模が大きい新機能のため、実装前に設計案(タブ構成・拡張の仕組み・提案する新規事業案)を提示し、
このラウンドでの実装範囲を確認した。「土台(事業スペース拡張の仕組み)+肉の販売のみフル実装、
魚・小麦等は次回以降のラウンドで追加」という方針で合意し、その範囲で実装した。

## 実装内容

### 市場タブの廃止
木材・食料の即時売買(`sell()`/`buy()`、`MARKET_RATES`、`renderMarket()`)を削除。木材の主な
収入源である拠点カウンター+客NPCの列の仕組みには影響しない。

### 新規事業タブの新設
ナビゲーションの同じ位置(旧・市場タブの場所)に「新規事業」タブを新設。`state.newBusiness =
{ spaceLevel:0 }`を新設し、「事業スペース拡張」(5000G基準×2.3^lv、最大5回)を購入するたびに
`spaceLevel`が1つ上がる。Lv.1で肉の販売(狩猟)が解放される設計とし、将来追加する魚・小麦などは
Lv.2以降に割り当てる想定(この仕組み自体は使い回す)。

### 拠点の東に新規事業スペース(狩猟エリア)を新設
北の門(森へ続く)と対になる形で、拠点の東壁に新しい門(東の門、`EAST_DOOR_X`)を新設。
事業スペース未解放の間は壁のまま(通行不可)、解放すると3マス幅の隙間が開く。門の先
(`HUNT_MIN_X`〜`HUNT_MAX_X`、7マス幅)に、独立した狩猟エリア(地面・柵・獲物6頭・肉販売
カウンター)を構築する。拠点拡張(北への拡張)とは完全に独立した軸の拡張で、拠点の東西幅
(`BASE_MIN_X`/`MAX_X`)自体は変更していない。

**実装中に発見・修正した不具合**: `blocked()`の判定順序が「まず z が拠点のz範囲内かどうかを
判定し、該当すればx方向の判定だけで確定させる」という構成だったため、狩猟エリアのz範囲が拠点の
z範囲と重なる(東西に並んでいるため当然ではあるが見落としていた)ことで、狩猟エリア自体の判定に
到達する前に拠点ゾーンの東壁判定でブロック済みとして確定してしまう不具合があった。各ゾーンを
「通れるならfalseを返す」独立した矩形判定の列挙に書き直し、該当するゾーンがなければ最後にtrueを
返す構成に修正した(実機テストで発見)。

### 肉の販売(狩猟)の実装
- `state.automation.hunting = { countLevel:0, speedLevel:0, hunters:[] }`を新設。伐採自動化と
  全く同じ「人数(countLevel)」「効率(speedLevel)」の2トラック構成とし、既存の`buyAutomation()`
  `automationRow()`にkind:"hunting"の分岐を追加する形で実装(新規の購入関数は作らず、既存の仕組みに
  合流させた)
- 獲物(鹿)はtreesと全く同じ考え方(`animals`配列、`nextAvailableAnimalIdx`/`assignHunterAnimal`/
  `ensureHunterTarget`/`updateHuntingWalk`/`processHunting`が、それぞれ木の伐採自動化の対応する
  関数と1:1で対応)。猟師は担当の獲物まで1マスずつ歩き、到着後`huntingSecondsFor(speedLevel)`
  秒(基準8秒、効率Lvごとに-0.5秒、下限3秒)で1頭仕留め、`MEAT_PER_ANIMAL(4)`の肉を**専用の収集
  ボックスを介さず直接**`state.resources.meat`へ加算する(木材・売買自動化と違い、意図的に1段
  シンプルな設計にして、今後の新規事業を追加しやすいテンプレートにした)
- 肉販売カウンター(`MEAT_SELL_PT`)は客NPCの列を置かず、近づいている間だけ肉が自動で売れる
  簡易な方式(`MEAT_SELL_RATE_PER_SEC=2`個/秒、`MEAT_PRICE=5`G/個)。客NPCの列を新規事業ごとに
  複製すると実装量が膨らみすぎるため、よりシンプルな方式を採用し、今後の魚・小麦などもこの方式を
  踏襲する想定
- 獲物が仕留められると`ANIMAL_RESPAWN_SECONDS(6秒)`後に再生する(木の`REGROW_SECONDS`と同じ方式)

### UI
- 新規事業タブに「現在の肉」表示(`#bizMeatStock`、`updateWoodPile`/`updateMeatDisplay`と同じ
  軽量更新パターンで、DOMノードを作り直さずtextContentだけ更新)と、事業スペース拡張+狩猟自動化
  2行(人数/効率)を表示。狩猟自動化の行は既存の`automationRow()`を再利用し、専用の`NEWBIZ_DEFS`
  辞書を介して表示する(効率化タブの`AUTOMATION_DEFS`とは別枠)
- `renderResBar()`に`refreshNewBizButtons()`(data-cost属性を持つボタンのdisabled状態だけを
  軽量に更新)を追加し、v0.23.0で確立した「DOMノードを作り直さない」パターンを新規事業タブにも
  適用した
- HUD左上のゾーン表示(`currentZoneLabel()`)が、プレイヤーが拠点の東壁を越えた位置にいる場合は
  「🥩 狩猟エリア」を表示するよう修正(従来はz座標だけで判定しており、x方向に拠点を越えても
  「拠点」のまま表示される抜け漏れがあった。実機テストで発見・修正)

## 動作確認
Browserペイン(localhost:8795)で確認。一時的なデバッグフック(`window.__giveGold`/`__dbg`/
`__buyNewBizSpace`/`__buyAuto`/`__setPos`/`__playerPos`/`__migrationTest`/`__tickHunting`/
`__sellMeatTest`)を仕込んで検証後にすべて削除(削除後にGrepで`window\.__`の残存なしを確認)。

- 事業スペース未購入の状態で、東の門・狩猟エリア中心点がいずれも`blocked()`でtrue(通行不可)で
  あることを確認
- 事業スペース拡張を購入 → 東の門・狩猟エリアがいずれも`blocked()`でfalse(通行可)になり、
  `world.huntGroup`/`world.eastDoor`が構築されることを確認(前述の不具合はこの過程で発見・修正)
- 狩猟自動化を人数・効率ともに1レベルずつ購入し、猟師が実際に獲物へ歩いて向かい、
  `huntingSecondsFor(1)=7.5秒`経過後に1頭仕留めて`MEAT_PER_ANIMAL(4)`の肉を獲得、該当の獲物が
  `gone`状態になることを確認。実時間経過後に`animal`状態へ正しく再生することも確認
- 肉販売カウンターでの自動販売(1秒あたり2個×5G=10G)の計算が理論値と一致することを確認
- 実際のキーボード操作(矢印キー押しっぱなし)で、拠点の出発地点から東の門を越えて狩猟エリアの
  奥まで正しく歩けることを確認(座標ベースのテレポートだけでなく、本物の移動処理での到達性も
  裏取り)
- 狩猟自動化の人数を2まで購入し、2体の猟師がそれぞれ別の獲物に割り当てられ、3Dシーン上にも
  2体とも正しく表示されることをスクリーンショットで確認
- 効率化タブ(伐採/売買/運搬自動化・拠点拡張)・雇用タブが従来通り動作し、新規事業タブの行と
  混ざらずに独立していることを確認。効率化タブのボタンを実際にクリックしてレベルアップできる
  ことも確認(v0.23.0のDOM書き換え回帰を踏まえた再発防止チェック)
- 拠点拡張(北へ4マス)を購入した後も、東の門・狩猟エリアの通行可否や表示が正しく維持される
  ことを確認(2つの独立した拡張軸が干渉しないことの裏取り)
- 新規事業タブの狩猟自動化ボタンを実際のクリックで操作し、ゴールドが正しく消費され猟師が
  増員されることを確認
- 旧セーブ(`automation.hunting`/`newBusiness`/`resources.meat`/`huntingLastTick`が存在しない
  形式)を`load()`に直接通し、すべて正しいデフォルト値で補われることを確認
- コンソールエラーなし(全工程で確認)
- テスト後、`localStorage`をクリアしてから最終セーブを確認
