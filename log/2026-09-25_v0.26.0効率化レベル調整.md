# 2026-09-25 v0.26.0 効率化レベル調整

## 経緯
v0.25.0に対するフィードバック(効率化レベル調整):

- 木材自動運搬は運搬効率とコンベア本数の2つにする
- 運搬効率はLv1毎に運搬速度上昇(Lv.1:1個/s_Lv.2:2個/s_Lv.3:3個/s_Lv.4:4個/s_Lv5:5個/s〜Lv.10:10個/s)
- コンベア本数はLv1毎にコンベア本数上昇(Lv.1:1本_Lv.2:2本_Lv.3:3本_Lv.4:4本_Lv5:5本〜Lv.10:10本)
- 木材の確保量/伐採速度/木材の単価のレベルは最大50
- 木の再生速度は1.5sで
- 木材伐採エリアを縦に(6マス)拡張+伴って木を2列追加

## 実装内容

### 木材自動運搬を本数/効率の2トラックに分離
これまで単一の`level`(導入と運搬速度強化を兼ねる)だった木材自動運搬を、伐採自動化・売買自動化と
同じ「本数(countLevel)」「効率(speedLevel)」の2トラックに再設計した。

- `state.automation.transport = { countLevel:0, speedLevel:0 }`(旧: `{level:0}`)
- **効率トラック**: `transportRateForLevel(lv) = lv` という単純な比例式(Lv.1=1個/秒 〜
  Lv.10=10個/秒、Lv.0=0個/秒)。指定どおりの直線的な対応
- **本数トラック**: コンベアの並行稼働数そのもの(Lv.N = N本)。台数が増えるたびに搬送のキャパシティ
  が線形に増える
- **合計運搬量 = 本数 × 1本あたりの効率**(`processTransport`で`t.countLevel * transportRateForLevel(t.speedLevel)`)
- 既存の`buyAutomation(kind, track)`(伐採・売買自動化と共通の購入関数)に`kind:"transport"`を
  追加する形で統合し、専用だった`buyTransport()`は廃止。`AUTOMATION_DEFS`に
  `transportCount`/`transportSpeed`を追加し、`automationRow()`・`renderEffList()`も既存の
  台数/効率パターンに合流させた(効率化タブの手書きの専用HTMLブロックも撤去し、他の自動化と
  同じ自動生成の仕組みに統一)
- コスト曲線は新設: 本数トラック600G×2.2^lv、効率トラック450G×2.0^lv(既存の伐採/売買自動化の
  コスト規模に揃えた)
- **3Dのコンベア表示も複数本対応**: `buildTransportBeltMesh(laneOffset)`が、経路全体を垂直方向に
  一律オフセットさせることで、平行な複数本のコンベアを描き分けられるようにした。ただし本数が
  増えるほど通路が窮屈になるため、見た目は最大4本までに間引いて表示する(`TRANSPORT_BELT_VISUAL_MAX`)
  — 搬送量の計算自体は本数どおり(最大10本)に反映される。各レーンの位置は生成時のインデックスで
  固定されるため、後から本数が増減しても既存のレーンが横にずれて見えることはない
- 効率(speedLevel)が0のうちは実際の搬送量も0になるため、コンベア上の木材の演出アニメーションも
  あえて静止させる(稼働していないのに動いて見える、という見た目と実態のズレを避けるため)
- **旧セーブ互換**: 旧`transport.level`が存在する場合、`countLevel = 1(導入済みなら)`、
  `speedLevel = 旧level`として引き継ぐ(これまでの投資を効率トラックの実績として保持しつつ、
  本数は最低限の1本からスタートする設計)

### 基本強化3種の上限を50へ
`UPGRADE_MAX`(木材の確保量・伐採速度・木材の単価が対象)を、他の自動化・拠点拡張と共有していた
`LEVEL_MAX`(10)から切り離し、独立した定数として50に設定。コスト曲線自体
(`upgradeCost(level) = round(6*1.6^level)`)は変更していないため、高レベル帯は指数的に高額になる
(長期的な伸びしろとして機能する想定)。自動化・拠点拡張の各トラックは引き続き`LEVEL_MAX=10`のまま。

### 木の再生速度の短縮
`REGROW_SECONDS`を10秒→1.5秒に変更。

### 森のさらなる拡張
`FOREST_MAX_Z`を`FOREST_MIN_Z+9`(10マス、v0.25.0時点)から`FOREST_MIN_Z+15`(16マス)へ+6マス
拡張。`TREE_DEFS`の木の行を`[+1,+3,+5,+7]`(4行)から`[+1,+3,+5,+7,+9,+11]`(6行、+2行)に拡張し、
既存の2マス間隔パターンをそのまま延長した。全28本→42本。地面・柵・`blocked()`はいずれも
`FOREST_MAX_Z`から動的に計算されるため、この2箇所の定数変更だけで整合的に反映される。

## 動作確認
Browserペイン(localhost:8795)で確認。一時的なデバッグフック(`window.__giveGold`/`__dbg`/
`__buyAuto`/`__beltCount`/`__transportRate`/`__setBoxWood`/`__tickTransport`/
`__upgradeMax50Test`)を仕込んで検証後にすべて削除(削除後にGrepで`window\.__`の残存なしを確認)。

- 木の総数が42本(6行×7本)、森の南北範囲がforestMinZ+15になっていることを確認
- 木の再生時間が1.5秒に設定されていることを確認
- 木材自動運搬の本数トラックを5回購入し、`countLevel=5`・コンベアの表示本数が上限どおり4本に
  なることを確認(内部の`countLevel`は5のまま、見た目だけが4本に間引かれている)
- 効率トラックを3回購入し、`transportRateForLevel(3)===3`(指定どおりLv.3=3個/秒)であることを確認
- 本数5・効率3の状態で2秒分の`processTransport`を実行し、運搬量が理論値(5本×3個/秒×2秒=30)と
  正確に一致することを確認
- 基本強化(木材の確保量)をLv.49から1回レベルアップしてLv.50に到達し、その後は購入してもLv.50の
  ままであること(MAX到達で正しく打ち止めになること)を確認
- 実際のUIクリックで木材自動運搬の本数トラックをレベルアップし(Lv.5→6)、ゴールドが正しく消費
  されることを確認
- 拠点拡張を購入した後もコンベアの表示本数(4本、見た目の上限)が維持され、エラーなく再構築される
  ことを確認
- 旧セーブ形式(`transport.level`のみ)を読み込ませ、`countLevel=1`・`speedLevel=旧level`へ
  正しく移行されることを確認
- 効率化タブのスクリーンショットで、木材自動運搬が伐採/売買自動化と同じ「本数/効率」の2行構成で
  表示され、基本強化がLv.50でMAX表示になっていることを確認
- 実際のキーボード操作でプレイヤーが正しく移動することを確認(今回の変更が既存の移動処理に
  影響していないことの裏取り)
- コンソールエラーなし(全工程で確認)
- テスト後、`localStorage`をクリアしてから最終セーブを確認
